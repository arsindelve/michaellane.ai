## The starting point

Twenty years of code in Subversion, manual builds, little automated testing and inconsistent review. The software ran hardware in the field, so mistakes were expensive and change was slow.

## What changed

- **Git and Azure DevOps**, with the full history migrated.
- **CI/CD pipelines**, so every change was built and tested the same way.
- **Automated unit testing** and **standard, rigorous code review** for every change.
- **Scrum**, giving the team a predictable rhythm and the business visibility into it.

Modernizing a legacy codebase is mostly about people: making the safe path the easy path, one habit at a time.
